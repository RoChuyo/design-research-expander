# Design Research Expander

## 核心规则

默认用中日双语回答和生成文档：先中文，后日文。除非用户明确要求只用一种语言，所有研究文档、案例图册、来源库、方向矩阵、方法计划、计划书改写稿、综合报告、Notion 副本和演讲稿都必须提供中文与日文两种版本或两栏内容。日文应使用自然、清楚、研究计划书可用的表达；中文应简明准确。两种语言都要避免生僻词、过难汉字、过度抽象的学术词和长句。必要术语可以保留，但第一次出现时用简单话解释。只有不可避免的专有名词、产品名、论文题名、URL、标准编号、数据库名或原始引用可以保留原文。不要为了中文化或日文化而翻译难以核验的论文题名或产品名。

使用这个 skill 将研究计划书转化为有资料依据、能激发灵感的产品设计研究扩展。必须同时关注学术论文/理论来源与真实产品/设计案例，因为产品设计研究通常既依赖概念空白，也依赖市场和产品先例。

当创建任何研究文档、资料夹、图片集、来源库、方向矩阵、方法计划或计划书改写文件时，默认使用中文命名，并按照任务类型建立分类文件夹。产品图片文件名必须包含产品名和 2-4 个中文特点总结词；案例图册或调研 Markdown 必须用本地路径插入图片，并在图片附近说明来源和可借鉴点。只有代码约定文件、系统必须识别的文件、原始下载文件或用户明确要求保留的文件名可以使用非中文命名。

当创建 `.md` 研究文档、案例图册、来源库、方向矩阵、方法计划、计划书改写稿或综合报告时，若 Notion 插件/连接器可用，必须同时在 Notion 中创建同内容副本，并在本地索引或原 Markdown 文档末尾记录 Notion 页面链接。Notion 副本的标题必须与 Markdown 中文文件名主体一致；若用户当前在 Notion 页面中工作，优先把副本创建为该页面的子页面；否则先搜索与研究计划书、项目名或主题最相关的 Notion 页面作为父页面。若无法确定父页面或没有 Notion 权限，仍然完成本地 Markdown，并在最终回复中明确说明 Notion 同步未完成及所需信息。

## 工作流程

1. 仔细阅读用户提供的研究计划书，提取设计对象、目标用户、使用场景、研究目标、拟用方法、预期产出、限制条件和不明确假设。
2. 内部生成中英文日文检索关键词，但最终分析必须用中日双语表达。必要时覆盖产品设计、交互设计、服务设计、HCI、人因工程、可持续设计、材料、无障碍、文化语境和市场品类等近义词。
3. 当用户需要真实证据、论文、现有产品、近期案例、市场样本、标准或“最新”信息时，必须检索/浏览当前资料，而不是只依赖记忆。优先使用可核验的一手或高可信来源：出版社页面、DOI 页面、会议论文集、大学页面、产品官网、专利页面、公司文档、设计奖项数据库、博物馆/档案页面、标准组织和可靠行业报告。
4. 建立两个资料池：学术/理论资料池，以及现有产品/案例资料池。不得编造引用、产品声明、日期、奖项、指标或 URL。无法核验的资料应标注“未核验”或直接省略。
5. 通过证据空白、用户需求、产品先例、技术可行性、材料/工艺限制、社会价值、可持续性、商业/生态适配和评估方法来综合生成研究机会。
6. 为每个方向估计工作量，给出等级、预计投入范围和原因。考虑文献深度、田野难度、原型保真度、技术依赖、制造/材料复杂度、参与者招募、评估工作量、伦理/隐私/IP 风险和截止日期匹配度。
7. 最后必须输出一段连续的中文启发性总结和一段对应的日文启发性总结，语气像研究导师在帮助用户打开想象。最终总结不能是项目符号、表格或分段列表。日文段落不要用过难词汇，优先使用学生可以直接讲出来的表达。
8. 如果需要把结果保存到本地，先建立中文项目资料夹，再根据任务将文件放入分类子文件夹；同时创建中文索引文档，说明每个文件的用途和阅读顺序。
9. 如果保存产品案例图片，先根据案例内容提炼特点总结词，再用 `编号_产品名_特点1_特点2_特点3.扩展名` 命名图片；在 Markdown 中使用 `![产品名：特点总结](/绝对路径/图片文件名)` 插入图片，避免只给图片链接或只列文件名。
10. 每次创建 Markdown 文档后，执行 Notion 同步检查：确认是否有可用 Notion 工具；确认父页面；把 Markdown 内容转换为 Notion 可接受的 Markdown；将本地图片路径替换为原始公开图片 URL 或写成“本地图片路径”说明；创建 Notion 页面；把返回的 Notion URL 记录到本地索引/文档和最终回复。

## 输出结构

除非用户要求其他格式，否则使用以下结构：

1. `对计划书的理解 / 研究計画書の理解`：用一个简洁中文段落和一个对应日文段落说明核心问题和设计机会。
2. `可用资料线索 / 使える資料の手がかり`：分别用紧凑表格整理文献/理论资料与现有产品/案例。包括资料名称、相关性、可贡献内容，以及可用链接或引用。表格内容优先中日双语；空间不足时，中文为主并附日文短句。
3. `可发展的研究方向 / 発展できる研究方向`：提出 4-8 个方向。每个方向包括方向标题、核心想法、证据依据、可能的产品/设计产出、建议方法、预计工作量、工作量原因、关键风险和第一步行动。方向标题必须中日双语。
4. `优先级建议 / 優先順位の提案`：排序最值得优先推进的 2-3 个方向，并用中日双语解释原因。
5. `整段启发性汇总 / ひと続きのまとめ`：用一个不中断的中文段落和一个对应日文段落整合可能路径，帮助用户想象项目可以如何发展。

## 资料与分析指引

当项目属于产品设计领域，需要更细的检索方式、方向发散维度、工作量等级或中日双语输出约束时，读取 `references/product-design-research-guide.md`。

当任务要求生成、保存、整理或归档文档、图片、案例图册时，读取 `references/document-archive-rules.md`，并遵循其中的中文命名、任务分类、图片命名、Markdown 插图、索引与版本管理规则。需要新建完整资料库时，可运行 `scripts/create_chinese_research_archive.py <中文项目名> --root <保存目录>` 来生成中文分类文件夹和 `00_资料夹索引.md`。

当任务创建 Markdown 文档且需要或可以同步到 Notion 时，读取 `references/notion-sync-rules.md`。Notion 同步是本地 Markdown 的副本流程，不应替代本地文件创建；如果两者内容需要差异，优先保证本地 Markdown 的图片绝对路径可渲染，Notion 版优先使用公开外链图片和可跨设备阅读的来源链接。

当回答依赖资料时，必须在答案中提供引用或链接。如果无法浏览，明确说明资料收集受限，请用户提供文件或链接，同时仍可基于已有计划书给出临时方向。
