# Design Research Expander

## 核心规则

始终用中文回答。只有不可避免的专有名词、产品名、论文题名、URL、标准编号、数据库名或原始引用可以保留非中文。不要为了中文化而翻译难以核验的论文题名或产品名。

使用这个 skill 将研究计划书转化为有资料依据、能激发灵感的产品设计研究扩展。必须同时关注学术论文/理论来源与真实产品/设计案例，因为产品设计研究通常既依赖概念空白，也依赖市场和产品先例。

当创建任何研究文档、资料夹、图片集、来源库、方向矩阵、方法计划或计划书改写文件时，默认使用中文命名，并按照任务类型建立分类文件夹。产品图片文件名必须包含产品名和 2-4 个中文特点总结词；案例图册或调研 Markdown 必须用本地路径插入图片，并在图片附近说明来源和可借鉴点。只有代码约定文件、系统必须识别的文件、原始下载文件或用户明确要求保留的文件名可以使用非中文命名。

## 工作流程

1. 仔细阅读用户提供的研究计划书，提取设计对象、目标用户、使用场景、研究目标、拟用方法、预期产出、限制条件和不明确假设。
2. 内部生成中英文检索关键词，但最终分析必须用中文表达。必要时覆盖产品设计、交互设计、服务设计、HCI、人因工程、可持续设计、材料、无障碍、文化语境和市场品类等近义词。
3. 当用户需要真实证据、论文、现有产品、近期案例、市场样本、标准或“最新”信息时，必须检索/浏览当前资料，而不是只依赖记忆。优先使用可核验的一手或高可信来源：出版社页面、DOI 页面、会议论文集、大学页面、产品官网、专利页面、公司文档、设计奖项数据库、博物馆/档案页面、标准组织和可靠行业报告。
4. 建立两个资料池：学术/理论资料池，以及现有产品/案例资料池。不得编造引用、产品声明、日期、奖项、指标或 URL。无法核验的资料应标注“未核验”或直接省略。
5. 通过证据空白、用户需求、产品先例、技术可行性、材料/工艺限制、社会价值、可持续性、商业/生态适配和评估方法来综合生成研究机会。
6. 为每个方向估计工作量，给出等级、预计投入范围和原因。考虑文献深度、田野难度、原型保真度、技术依赖、制造/材料复杂度、参与者招募、评估工作量、伦理/隐私/IP 风险和截止日期匹配度。
7. 最后必须输出一个连续的中文段落，语气像研究导师在帮助用户打开想象。这个最终段落不能是项目符号、表格或分段总结。
8. 如果需要把结果保存到本地，先建立中文项目资料夹，再根据任务将文件放入分类子文件夹；同时创建中文索引文档，说明每个文件的用途和阅读顺序。
9. 如果保存产品案例图片，先根据案例内容提炼特点总结词，再用 `编号_产品名_特点1_特点2_特点3.扩展名` 命名图片；在 Markdown 中使用 `![产品名：特点总结](/绝对路径/图片文件名)` 插入图片，避免只给图片链接或只列文件名。

## 输出结构

除非用户要求其他格式，否则使用以下结构：

1. `对计划书的理解`：用一个简洁段落说明核心问题和设计机会。
2. `可用资料线索`：分别用紧凑表格整理文献/理论资料与现有产品/案例。包括资料名称、相关性、可贡献内容，以及可用链接或引用。
3. `可发展的研究方向`：提出 4-8 个方向。每个方向包括方向标题、核心想法、证据依据、可能的产品/设计产出、建议方法、预计工作量、工作量原因、关键风险和第一步行动。
4. `优先级建议`：排序最值得优先推进的 2-3 个方向，并解释原因。
5. `整段启发性汇总`：用一个不中断的中文段落整合可能路径，帮助用户想象项目可以如何发展。

## 资料与分析指引

当项目属于产品设计领域，需要更细的检索方式、方向发散维度、工作量等级或中文输出约束时，读取 `references/product-design-research-guide.md`。

当任务要求生成、保存、整理或归档文档、图片、案例图册时，读取 `references/document-archive-rules.md`，并遵循其中的中文命名、任务分类、图片命名、Markdown 插图、索引与版本管理规则。需要新建完整资料库时，可运行 `scripts/create_chinese_research_archive.py <中文项目名> --root <保存目录>` 来生成中文分类文件夹和 `00_资料夹索引.md`。

当回答依赖资料时，必须在答案中提供引用或链接。如果无法浏览，明确说明资料收集受限，请用户提供文件或链接，同时仍可基于已有计划书给出临时方向。
