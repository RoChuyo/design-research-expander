# 文档命名与归档规则

## 总原则

当使用本 skill 创建研究资料、调研报告、案例图册、来源库、计划书改写稿或图片资料夹时，优先使用中文命名，并按照任务类型归档。目标是让用户不需要打开文件也能从文件名判断内容。

保留非中文名称的例外：

- 原始文件名需要保留以便追溯，例如用户上传的 PDF。
- 代码或系统约定文件，例如 `SKILL.md`、`openai.yaml`。
- DOI、论文标题、产品名、品牌名、标准编号等专有名词。
- 用户明确要求使用英文或其他语言命名。

## 项目资料夹命名

默认在用户指定目录创建项目资料夹；若用户未指定，优先使用 `~/Documents`。资料夹名称使用中文短语，必要时加日期或主题：

- `陶土表面痕迹产品设计研究`
- `产品设计研究资料_陶土纹理与通用设计`
- `研究计划书扩展资料_陶土CMF`

避免使用含义不明的名称，例如 `outputs`、`research`、`notes`、`new folder`。

## 分类文件夹模板

根据任务需要创建最少必要文件夹，不必每次全部创建：

| 文件夹名 | 内容 |
|---|---|
| `00_原始资料` | 用户提供的 PDF、图片、原始文本抽取、未加工材料。 |
| `01_资料来源` | 文献、网页、产品案例、设计奖项、标准、专利等来源库。 |
| `02_案例图册` | 产品案例图片、案例分析、图片来源说明。 |
| `03_方向矩阵` | 研究方向、产品方向、工作量估算、优先级矩阵。 |
| `04_方法计划` | 调研方法、访谈计划、样本制作、评价量表、时间线。 |
| `05_计划书改写` | 研究目的、研究意义、研究问题、预期成果等可直接替换文本。 |
| `06_综合报告` | 主报告、阶段总结、最终整合报告。 |
| `07_图片资料` | 下载图片、示意图、截图、视觉参考。 |
| `08_中间文件` | 临时抽取文本、草稿、待整理资料。 |
| `99_归档` | 过时版本、旧稿、备份。 |

如果用户的任务是单一主题，可以创建更贴近任务的二级文件夹，例如：

- `02_案例图册/通用设计与老人用品`
- `02_案例图册/医用器械与康复产品`
- `01_资料来源/触觉设计文献`
- `04_方法计划/用户访谈与评价量表`

## 文件命名规则

文件名使用中文，并用两位数字保持阅读顺序：

- `00_资料夹索引.md`
- `01_主报告_陶土表面痕迹转译.md`
- `02_资料来源库_文献与产品案例.md`
- `03_研究方向矩阵_工作量与风险.md`
- `04_调研方法与评价计划.md`
- `05_计划书改写_研究目的与意义.md`
- `06_案例图册_陶土与陶瓷产品.md`
- `07_案例图册_通用设计与医用器械.md`

## 产品图片命名规则

产品图片文件名必须让用户在文件夹中直接看出“是什么产品、有什么特点、为什么被收集”。命名格式：

`编号_产品名_特点1_特点2_特点3.扩展名`

规则：

- 编号使用两位数字，保持案例顺序，例如 `01`、`02`。
- 产品名或品牌名可以保留原文，例如 `Print-Clay-Humidifier`、`Haptique`。
- 特点总结词使用中文，优先 2-4 个词，避免过长。
- 特点词要描述与研究相关的表面、功能、对象或情绪价值，例如 `陶土孔隙`、`自然加湿`、`压纹握持`、`触觉引导`、`老人安全`、`裂纹透光`、`功能分区`、`低视觉识别`。
- 不要只写来源名，例如 `red-dot`、`ifdesign`；来源应写在 Markdown 说明或来源库中。

示例：

- `01_Print-Clay-Humidifier_陶土孔隙_自然加湿_可持续材料.jpg`
- `02_One-o-One_陶瓷旅行杯_压纹握持_触觉愉悦.jpg`
- `03_Haptique_结构化表面_老人安全_触觉握持.jpg`
- `04_VerSkin_凸点定位_颜色分区_低视觉识别.jpg`

## Markdown 插图规则

案例图册、产品调研、视觉参考和方法说明文档中，只要已经下载了图片，就必须直接插入本地图片路径，而不是只列 URL 或文件名。使用 Markdown 图片语法：

```markdown
![产品名：特点总结](/绝对路径/图片文件名.jpg)
```

图片附近必须包含：

1. `来源`：原始网页或图片来源链接。
2. `核心信息`：该案例已核验的事实。
3. `与本研究的关联`：为什么这个案例被收集。
4. `可借鉴点`：可转译成研究方向、原型或评价指标的做法。

优先使用绝对路径，确保 Codex 桌面端可以直接渲染本地图片。不要使用 `file://`、相对路径或只有文字描述的“见图片文件夹”。

## 索引文档

每个项目资料夹都应创建中文索引文档，优先命名为 `00_资料夹索引.md`。索引中写明：

1. 项目目的。
2. 文件夹结构。
3. 推荐阅读顺序。
4. 每个文档的用途。
5. 最重要的结论或下一步行动。

如果需要兼容常规工具，可以额外保留 `README.md`，但主要索引仍使用中文文件名。

## 版本与覆盖规则

不要覆盖用户已有文件，除非用户明确要求更新该文件。若需要创建新版本，使用：

- `研究目的与意义_第2版.md`
- `通用设计案例图册_2026-05-15.md`
- `资料来源库_补充老人医用方向.md`

若需要归档旧版本，将旧文件移动到 `99_归档`，并在索引中说明。

## 输出前检查

完成文件创建后，检查并告知用户：

- 项目资料夹路径。
- 新增或更新了哪些中文文件。
- 图片或原始资料放在哪个分类文件夹。
- 是否有未核验、待补充或需要用户确认的来源。
