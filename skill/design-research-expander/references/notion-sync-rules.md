# Notion 副本同步规则

## 适用场景

当本 skill 创建以下 Markdown 文档时，默认同步一份 Notion 副本：

- 研究主报告、阶段总结、综合报告。
- 资料来源库、文献综述、案例图册。
- 研究方向矩阵、工作量估算、优先级建议。
- 调研方法、访谈计划、评价量表、时间线。
- 计划书改写稿、研究目的与意义、研究问题与预期成果。

如果用户明确说“不需要 Notion”“只创建本地文件”或 Notion 连接不可用，则只创建本地 Markdown，并在最终回复说明未同步原因。

## Notion 页面创建位置

优先级如下：

1. 如果用户当前正在某个 Notion 页面中工作，并且任务明显属于该页面主题，将新页面创建为当前页面的子页面。
2. 如果用户提供了 Notion 页面或数据库链接，先用 Notion fetch 工具读取，确认可写入后作为父页面或数据源。
3. 如果未提供链接，搜索研究计划书标题、项目名、关键词或用户当前资料主题，选择最相关的 Notion 页面作为父页面。
4. 如果搜索结果不明确，不要随意创建到错误页面；先完成本地 Markdown，并请用户提供 Notion 父页面链接。

## 标题与命名

Notion 页面标题应与 Markdown 文件名主体一致，去掉编号和 `.md` 后缀，但保留中文主题。

示例：

- `06_综合报告/研究资料总览_陶土表面痕迹与产品设计转译.md`
- Notion 标题：`研究资料总览：陶土表面痕迹与产品设计转译`

标题中的下划线可改为中文冒号、顿号或空格，使其更适合 Notion 阅读。

## 内容转换

Notion 副本应尽量保持与本地 Markdown 同结构，包括标题、表格、案例说明、来源链接和总结段。转换时注意：

- 保留中文标题层级。
- 保留来源链接，优先使用 Markdown 链接格式。
- 保留表格，但避免过宽；过宽表格可拆成更短的表格或小节。
- 不要把本地绝对路径图片直接作为 Notion 图片嵌入，因为其他设备通常无法显示。
- 对已经下载的本地图片，Notion 版优先使用原始公开图片 URL；若没有公开图片 URL，则写明 `本地图片路径：/绝对路径/图片文件名`。
- 如果 Notion 不支持某种 Markdown 扩展，改用普通标题、段落、列表和表格表达。

## 图片同步规则

本地 Markdown：

```markdown
![产品名：特点总结](/绝对路径/图片文件名.jpg)
```

Notion 副本：

```markdown
![产品名：特点总结](https://原始图片或产品页可访问图片链接.jpg)
```

如果只有产品页链接而没有稳定图片链接，可以在 Notion 中写：

```markdown
**图片参考**：[产品来源页面](https://example.com/product)

本地图片路径：`/绝对路径/图片文件名.jpg`
```

## 本地回写记录

Notion 页面创建成功后，必须把 Notion URL 记录到以下至少一处：

1. 项目 `00_资料夹索引.md` 或 `README.md`。
2. 新创建 Markdown 文档末尾的 `Notion 副本` 小节。

推荐格式：

```markdown
## Notion 副本

- [页面标题](https://www.notion.so/...)
```

如果 Notion 同步失败，也记录原因：

```markdown
## Notion 副本

- 未同步：未能确定 Notion 父页面，请提供目标页面链接后重试。
```

## 最终回复

完成后在最终回复中说明：

- 本地 Markdown 路径。
- Notion 页面链接。
- 图片处理方式：本地使用绝对路径，Notion 使用公开图片链接或本地路径说明。
- 若同步失败，说明失败原因和下一步需要用户提供的信息。
